# Exchange copilot and visual review

Authorized 29 October 2026: implement the work possible without a merchant or recruited study participants.
Scope: read-only tool-using copilot for appearance-related tops, request-specific review of public
synthetic recorded previews, a separate evaluation suite, and evidence-delivery diagnosis. Merchant
onboarding and participant studies wait. Existing frozen YouCam studies and original assets stay unchanged.

The copilot can inspect confirmed requests, query eligible alternatives, explore one shopper-selected
limit and inspect available image-review evidence. It cannot save preferences, create previews, quote,
submit an exchange or spend YouCam units. The existing shopper confirmations remain authoritative.
Before confirmation, it reuses the interpreter's proposed controls and clarification questions.

Vision reviews inspect only garment attributes in hash-verified public synthetic recordings. They
report supports / concern / unclear per requested attribute, with visible evidence and an explicit
AI-only label. They cannot establish physical fit, comfort or overall fidelity. Shopper uploads and
combined looks are outside this version's model-review scope. No confidence percentage is shown.

The API adapters use no automatic retries, token preflight, bounded tool rounds, a separate atomic
USD reservation ledger and shared call limits for the two new features. Errors and unknown billing outcomes retain
conservative reservations. Hosted paid features remain disabled until a reviewed paid run and explicit
limits are approved. A prepared pilot will name exact cases, models, maximum calls and USD cap.

The evaluation separates deterministic contracts, fake-client failures, model assessments and any
future human labels. Synthetic tasks do not count as shopper feedback. Model agreement is not human
accuracy. Public reporting keeps unattempted, failed and uncertain outcomes visible.

## Prepared paid pilot and judge-only allowance

Proposed cumulative cap: **USD 3.00** across this pilot, at most one versioned repair run, and subsequent
judge-only use. Each registered run has 6 copilot cases (at most 4 calls each) and 6 already-published
synthetic image cases assessed by Sonnet 5.5 and Haiku 5.5: at most 36 generation calls per run, 72 over
two runs. No YouCam calls or new renders. The two reviewers belong to the same model family; agreement
is descriptive and is not independent human accuracy. Earlier failures remain in the report.

The conservative reservation maximum is USD 1.425 per full run, based on the official rates checked on
29 October, 90,000 reserved input tokens and 1,000 maximum output tokens per call. Token preflight must
be at most 30,000. No network retries. Stop a run on its first failed or uncertain request/contract;
uncertain billing blocks another run until resolved. A second run needs its own committed registration,
the same image/case coverage and the retained first report. It is used only if an observed problem
requires a repair. The USD 3 cumulative ledger still applies.

If the pilot meets its operational contracts, a deployed judge-only mode may use the remaining
approved USD allowance after subtracting local charged and reserved costs. The production ledger starts
with that smaller allowance, never another USD 3. Proposed limits: 24 model calls per UTC day and 12
per judge session, plus the cumulative USD cap. Legacy helpers remain on rules, YouCam stays mock with
zero unit caps, and personal uploads never go to the visual-review model. The original deployment plan
requires approval with numbers before a new paid stage; this paragraph is a proposal, not approval.

## Approval and first run

The owner approved **USD 3 total** on 29 October 2026 for up to two versioned pilot runs and subsequent
judge-only use from the remaining allowance, with 24 calls/day, 12/session and no YouCam calls.
Run 1 completed all six copilot tool contracts and two complete image-review pairs. It stopped at the
third case after the second model exceeded the observation length and inserted a prohibited verification
disclaimer. Charged USD 0.029854, reserved USD 0. No uncertain billing occurred. The first registration,
report and private response audit are retained. This is a failed model-output contract, not a fidelity
accuracy measurement.

The single approved repair is assessor v2: explicit short visible observations, criterion-specific
findings, and no repeated disclaimers inside observations. Validation remains strict. Known no-request
allowance/preflight blocks are distinguished from uncertain paid calls, and any uncertain charge stops
all later generation requests. A new registration precedes run 2; the six cases and image bytes stay the
same. No third pilot run is authorized.

## Repair outcome

Run 2 completed **6/6 model tool plans** and **12/12 assessments across the same six known images**.
The two models agreed on 11/12 requested-attribute findings. On the known sleeve-concern output,
Sonnet raised a concern while Haiku reported support; the recorded result marks that detail unclear.
Agreement is not accuracy and there are still zero independent human labels. Run 1 remains visible.
Total local recorded cost across both runs: **USD 0.091508**, with zero reservations or uncertain calls.
The maximum remaining judge-only production allowance is therefore **USD 2.908492**, from the same
approved USD 3 total. Neither legacy helper usage nor any new YouCam rendering is enabled by this cap.

The observer retained private response identifiers and generated text/tool blocks for both runs,
without request images, credentials or private model reasoning. Only audit hashes and approved public
assessment content enter the repository. The deployed ledger must keep its smaller remaining cap
across upgrades; it must not reset after a new image or session.
